How AEGIS works

Six agents. One governance outcome.
Every decision explained.

From the moment a Documentation Lead submits an intake form — or a regulator requests an audit trail — six system components fire in sequence. The simulation above shows each one in real time. Every agent produces a plain-language explanation of its decision before passing control to the next.

01
Intake Agent validates the submission
All mandatory fields checked against the Model Documentation Minimum Standards Policy. Missing fields blocked at the gate. No incomplete submission reaches classification.
→ Intake Agent · L2
01
02
Policy context loaded from Cloud Storage
All three governance policies fetched from GCP Cloud Storage and injected into the agent system prompt. Policy changes take effect immediately — no re-embedding, no index rebuild.
→ Policy Context Loader · L3
02
03
EU AI Act risk tier classified by Gemini
Classification Agent sends the intake payload + Annex III criteria to Gemini 2.0 Flash. Returns risk tier (Prohibited / High-Risk / Limited / Minimal) with the exact criterion that triggered it.
→ Classification Agent · Gemini · L2/L3
03
04
Oversight requirements determined
Oversight Agent uses the risk tier to determine who must review, what they must verify, and what constitutes a valid approval record. High-risk systems require qualified SME + Compliance Officer sign-off.
→ Oversight Agent · L2
04
05
Every decision explained in plain language
Explainability Agent wraps every preceding decision: what was decided, which policy clause triggered it, and what the Documentation Lead must do next. No black boxes. No unexplained classifications.
→ Explainability Agent · L2
05
06
Audit package written to Firestore
Audit Agent assembles the complete Annex IV evidence bundle: intake record, risk classification, oversight log, version history, policy citations — timestamped and immutably persisted to Firestore. Regulator-ready in under 4 minutes.
→ Audit Agent · Firestore · L2/L4
